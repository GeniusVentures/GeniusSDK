## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem → caller | dev_config.json read from base_path — caller controls filesystem; tampering expected |
| Caller → SDK init | dev_config JSON string crosses C ABI boundary — parsed by RapidJSON in SDK |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | dev_config.json on filesystem | accept | Caller controls base_path — if attacker can write files there, they already own the process. SDK doesn't validate JSON beyond required fields. |
| T-01-07 | Denial of Service | Missing dev_config.json | mitigate | Callers check file existence before calling init; SDK returns nullptr for empty/null dev_config (D-05). No crash path. |
| T-01-08 | Information Disclosure | Hardcoded private key in SDKIdleExample | accept | Example-only key (`deadbeef...` * 32) — explicitly a demo/test key. Not used in production. Acceptable for example code. |
| T-01-09 | Elevation of Privilege | CLI arg injection in service.cpp | mitigate | service.cpp accepts only `base_path` positional arg (1 arg after argv[0]); no shell-injectable flags remain. `base_path` is passed as-is to file open — if caller controls argv[1], they already own the process. |
</threat_model>
